## Concepts learned
- **Listen to your tests** — when code is hard to test, that's design feedback. Not being able to test the stdin bug led straight to I/O injection (`run`).
- **Dependency injection of I/O** — pass `io.Reader`/`io.Writer` in, so the same code runs on the terminal and in tests (`app/main.go` `run`).
- **`io.Reader` / `io.Writer` and implicit interfaces** — one-method interfaces that any type satisfies by having the method; `fmt.Fprint*` writes to any writer.
- **Buffered reader lifetime** — `bufio.Reader` reads ahead, so it must live as long as the stream; one per iteration loses buffered lines (bug #1).
- **Separate deciding from doing** — the `exit` handler decides to stop and returns that; `main` does the `os.Exit`, which makes `exit` testable.
- **A command result is more than a string** — output, exit code, and whether to stop; an exit code alone can't say "stop", because every command has one.
- **Exit status is a separate channel** — set with `os.Exit`, read by the parent as `$?`; not printed, not returned from `main`.
- **Test through the contract** — "don't test private methods" is about behaviour, not capitalization; `run` is the program's stdin→stdout contract.
- **Preparatory refactoring** — "make the change easy, then make the easy change"; refactor when a stage fights the design.
- **Functional core, imperative shell** — keep parsing pure (a function on a string) and push I/O to the edge; the parser shouldn't own the reader.
- **Layers in an interpreter** — transport/app/domain/infrastructure map onto a shell, but parsing is *domain* here, because the language is the product.

## Design decisions
- `run(io.Reader, io.Writer) int` — alternatives: return a `string` (output only appears after input ends). The shell must write as it goes.
- Handlers return a `HandlerResult` struct — alternatives: `(string, int)`, which can't tell "echo succeeded" from "exit 0". A struct names the fields and can grow.
- `run` owns newlines; handlers return plain text.
- Keep one package for now; treat layers as conceptual boundaries until one is worth protecting.
- Parser stays a pure function, separate from reading (agreed, not implemented yet).
