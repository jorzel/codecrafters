## Concepts learned
- **Outside-in TDD** — start from the outer edge (command registered, empty reply) and let failing tests drive the inside; the missing-key test was the first goal.
- **RESP replies are nested** — an array element can be any RESP value, so an XRANGE entry is an `Array` of a bulk string and a `BulkArray`. `protocol.Array` takes pre-encoded `[]string`, so nothing stops a raw string from going in.
- **`Parse…` vs `New…`** — Go names text → value conversions that can fail `Parse…` (`strconv.ParseInt`, `time.Parse`); `New…` builds from parts you already have.
- **Value objects** — `StreamID` has no identity and is compared by value; what makes it a value object is that you can't build an invalid one.
- **Make illegal states unrepresentable** — a stored entry's ID is always concrete, but `StreamID` also allows `*`/`+`, which is why `CompareIDs` panics. Idea: a separate type for XADD's input.
- **Two named functions over a flag** — `ParseRangeStart`/`ParseRangeEnd` read better than `ParseRangeBound(s, true)`; the only difference is the default sequence for `"1"`.
- **Names must say what the code does** — `parseConcrete` would have lied because the block also returns `IDMsAuto`; renamed to `parseMsAndSeq`.
- **Shared mutable state needs a lock on reads too** — `Range` reads `sr.items` while XADD may append.
- **Go map iteration order is random** — by design; insertion order needs a slice. Real Redis stores entry fields as an ordered flat list.
- **Exported vs unexported** — lowercase names are visible only inside their package, so `commands` and `storage_test` can't read `fields`.
- **`append` with a slice** — pass values (`append(s, a, b)`) or spread with `...`.

## Design decisions
- Range parsing lives in `storage` next to `StreamID` — alternative: parse in the handler. ID syntax is stream domain knowledge, and XADD shares it.
- `-`/`+` map to concrete min/max only in the range parsers — alternative: change `parseStreamID`, which would let XADD accept `+` as a real ID.
- The range-end default checks whether the sequence was given — alternative: another symbolic `IDType`, which `AddItem` and `CompareIDs` would then have to handle.
- XRANGE on a missing key returns an empty array, like real Redis — alternative: an error.
- Fields stored as `[]Field` — alternative: a flat `[]string`.
- The `StreamID` split is deferred until after XRANGE — this stage didn't require it.
