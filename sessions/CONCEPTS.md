# Concepts

A living index of broad concepts across sessions, sorted alphabetically.
When a concept comes up again, add a session link and sharpen its summary.
Details stay in the session files.

| Concept | Summary | Challenge | Sessions |
|---------|---------|-----------|----------|
| Architecture of an interpreter | Keep logic pure (functional core) and push I/O to the edge (imperative shell). Layers map onto a shell, but parsing is domain, because the language is the product | shell | [001](001-2026-10-14-shell.md) |
| Command lookup and execution in a shell | Builtins first, then PATH in order; a match is a regular file with an execute bit. PATH is user data, so failures mean "try the next entry". bash caches lookups lazily, zsh can fill its table up front. Running uses `execve(path, argv)`: the file to load and `argv[0]` (the short name) are separate, mirrored by `exec.Cmd.Path`/`Args` | shell | [002](002-2026-10-15-shell.md), [003](003-2026-10-15-shell.md) |
| Concurrent access to shared state | A thread-safe map makes single calls safe, not get → modify → set sequences; shared data needs a lock on reads as well as writes. Real Redis avoids most of this by running commands on one thread | redis | [005](005-2026-11-25-redis.md) |
| Encoding a wire protocol | RESP values nest: an array element can be any RESP value, so replies are built by composing encoders. Encoders that take pre-encoded strings can't stop raw text slipping in; typed reply builders can | redis | [005](005-2026-11-25-redis.md) |
| Error handling across boundaries | Adapters translate OS-specific errors into what the core understands, so the core doesn't import `os/exec` or `os`. Tell failure kinds apart (couldn't start vs exited non-zero) with `errors.As` | shell | [003](003-2026-10-15-shell.md) |
| Go's I/O model | `io.Reader`/`io.Writer` are one-method interfaces satisfied implicitly; wrappers like `bufio.Reader` add behaviour, and a buffered reader must live as long as its stream. A process has separate stdout and stderr; pass writers to the code that produces output. `Fprintf` for placeholders, `Fprintln` for fixed strings or plain values; `go vet` catches the mix-ups | shell | [001](001-2026-10-14-shell.md), [003](003-2026-10-15-shell.md), [004](004-2026-10-19-shell.md) |
| Interfaces and dependency injection in Go | The consumer owns the interface ("accept interfaces, return structs"); implicit satisfaction connects them; `main` is the composition root. Inject a capability, not a snapshot of data; every adapter that talks to the OS (filesystem, processes) gets its own port. Inject only when the real thing makes tests slow, flaky or hard to set up (`os.Getwd` doesn't, `os.Chdir` will) | shell | [002](002-2026-10-15-shell.md), [003](003-2026-10-15-shell.md), [004](004-2026-10-19-shell.md) |
| Modelling command results | Output is not part of the result: commands write to the streams they are given, like real processes. The result carries only exit code and "should stop"; the exit status is a separate channel (`os.Exit`, `$?`). POSIX codes: 0 success, 1 failure, 126 not executable, 127 not found | shell | [001](001-2026-10-14-shell.md), [003](003-2026-10-15-shell.md), [004](004-2026-10-19-shell.md) |
| Package and API design | Name packages after what they provide, avoid stutter, export only what callers need (lowercase names stay inside the package). Deep modules over shallow layers; comma-ok over sentinels when absence is possible. Name related things as one consistent group (`stdin`/`stdout`/`stderr`, `ExecutableFinder`/`ExecutableRunner`, `exit*` constants in one `const` block). `Parse…` for text → value that can fail, `New…` for building from parts; two named functions over a boolean flag; a name must stay true for everything the function returns | shell, redis | [002](002-2026-10-15-shell.md), [003](003-2026-10-15-shell.md), [004](004-2026-10-19-shell.md), [005](005-2026-11-25-redis.md) |
| Testability as design feedback | Hard-to-test code is design feedback. Inject I/O and dependencies, test through the contract (external `_test` packages), and fake only at boundaries (spy fakes record calls); test the adapters themselves against the real OS. Watch every test fail once, and drop tests that duplicate another. A value nobody reads (an unreturned exit code) or a branch no test covers is unchecked behaviour. Outside-in TDD: make the outer edge pass first and let failing tests drive the inside. A test that fails only sometimes points at hidden nondeterminism (Go map order) | shell, redis | [001](001-2026-10-14-shell.md), [002](002-2026-10-15-shell.md), [003](003-2026-10-15-shell.md), [004](004-2026-10-19-shell.md), [005](005-2026-11-25-redis.md) |
| Value objects and invariants | A value object has no identity, is compared by value, and can't be built invalid (validate in `Parse…`). Make illegal states unrepresentable: a type that allows states the domain forbids pushes checks (or panics) onto every caller | redis | [005](005-2026-11-25-redis.md) |
| When to refactor | Preparatory refactoring: refactor when a stage fights the design ("make the change easy, then make the easy change"). Extract a package when a stage forces that boundary, not up front. A refactor the stage doesn't need waits until the tests are green | shell, redis | [001](001-2026-10-14-shell.md), [002](002-2026-10-15-shell.md), [005](005-2026-11-25-redis.md) |
