## Concepts learned
- **Injecting a capability, not data** — a lookup interface instead of a precomputed list avoids staleness and cost; bash looks commands up lazily and caches them in a hash table (`hash`), while zsh can fill its table up front and needs `rehash`.
- **Comma-ok vs sentinel** — `(string, bool)` makes "might not exist" explicit in the signature; `os.Getenv` vs `os.LookupEnv` shows a sentinel turning ambiguous (`pathlookup.go:17`).
- **Fail fast vs tolerant input** — fail fast is for programmer errors; PATH is user data full of junk, so each entry is a guess and the search tolerates failure.
- **Unix permission bits** — octal `0o755`, owner/group/others, masks like `0o111`; `IsRegular()` rules out directories; `os.Stat` follows symlinks; real shells ask the kernel (`access(X_OK)`) instead (`pathlookup.go:31`).
- **Parse inputs once, query the world every time** — split PATH in `New`, `Stat` on every `Find`.
- **Consumer-owned interfaces / "accept interfaces, return structs"** — `shell` declares `ExecutableFinder`, `pathlookup.New` returns a concrete type, and Go connects them implicitly at the assignment (`repl.go:11`, `main.go:11`).
- **Compile-time interface assertion** — `var _ I = (*T)(nil)` is only needed when nothing in the program uses the type through the interface.
- **Composition root** — `main` is the only place that touches the real world and wires the pieces together (`main.go:10`).
- **Package naming** — name packages after what they provide (`shell`, `pathlookup`), not layers (`app`, `domain`, `infra`); avoid stutter (`pathlookup.PathLookupFinder`).
- **Shallow vs deep modules** — an "orchestration layer" that only forwards calls would be shallow; `Find` hides PATH splitting and permission checks behind one method.
- **Method values and initialization order** — `sh.typeHandler` in the map needs `sh` to exist first (`repl.go:20`).
- **Single source of truth** — `typeHandler` asks the handler map instead of a separate `COMMANDS` list (`repl.go:69`).
- **Go zero values** — fields left out of a struct literal get their zero value (`false`, `0`, `""`), so `shouldExit: false` is noise.
- **Test packages and fakes** — `package x_test` restricts tests to the public API; a one-method fake (`fakeFinder`) replaces temp dirs at the boundary.
- **`go test` package patterns** — `./app` vs `./app/...`; `-count=1` bypasses the cache.

## Design decisions
- Lookup interface `Find(name) (string, bool)` — alternative: inject a precomputed list of executables (stale, expensive, loses PATH order).
- Separate `pathlookup` package — alternative: keep everything in `main`. The filesystem lookup is real infrastructure with its own tests.
- Constructor takes the raw PATH string, and splitting happens inside — alternative: take `[]string`, which leaks the format to callers.
- No PATH validation in `New` — PATH is user data; a missing directory means "try the next one".
- Comma-ok over an empty-string sentinel — explicit beats implicit.
- Empty PATH entries: left as is (behaves like POSIX "current dir"). Choosing a policy (POSIX vs Go's `ErrDot`) is a separate decision.
- Interface owned by `shell`, `pathlookup.New` returns a concrete type — alternative: interface in `pathlookup`.
- Extract `shell` package, with `main` as composition root — alternatives: split into files within `package main`, or add an extra orchestration layer (shallow for now).
- `typeHandler` as a method on `*Shell`; `echo`/`exit` stay plain functions — alternative: closures capturing only the finder.
